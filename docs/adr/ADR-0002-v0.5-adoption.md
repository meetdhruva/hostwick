# ADR-0002: v0.5 "reasons to switch" — design and team contracts

Status: accepted, 2026-11-25. Scope: six workstreams built in parallel by
separate builders, merged by an integrator, then independently reviewed.

Goal of the release: give users of other tools a reason to switch, a painless
way to bring their hosts, and remove the gaps that block them. Signed
installers and distribution are deliberately out of scope.

## Rules for every workstream

1. **Branch**: `v05/<slug>` off `main`. Do not bump the version. Do not push
   to `main` or `release`.
2. **Ownership**: put the feature in its own crate/modules (listed below).
   Edits to shared files (`apps/desktop/src/app.rs`, `app/*.rs`,
   `settings.rs`, `settingsform.rs`, `hostform.rs`, `shortcuts.rs`,
   `app/palette.rs`, `backend.rs`, `hostwick-core`) are small hooks only: a
   field, a match arm, one call into your module.
3. **Strings**: every user-visible string goes through `t!` and exists in all
   8 locales. Append your keys in ONE block at the END of each
   `apps/desktop/locales/*.ftl` under `# --- v0.5 <slug> ---`.
4. **CHANGELOG**: add `### <Workstream>` under `## Unreleased` (create the
   heading at the top if absent). README: your own section or subsection.
5. **Keys**: app shortcuts must not take keys the shell needs; the existing
   test in `shortcuts.rs`/`terminal/keys.rs` enforces this. Reserved for this
   release: `Ctrl+Shift+I` (⌘I) AI assistant, `Ctrl+Shift+J` (⌘J) tunnels,
   `Ctrl+Shift+Y` (⌘Y) theme picker. Register in the shortcuts registry,
   cheat sheet and command palette.
6. **Never block the UI thread** (network, disk walks, crypto, parsing of
   large files run on the Tokio runtime / `spawn_blocking`).
7. **Untrusted input**: server output, imported files and model output are
   untrusted. No panics, bounded buffers, no command built by string
   concatenation (use the portable shell helper in `hostwick-sftp::shell`).
8. **Secrets** live in the vault under a credential id; never in profiles,
   settings, sync files, logs, notifications or error text.
9. **Dependencies**: rustls only (no OpenSSL/native-tls), licences allowed by
   `deny.toml`, `cargo deny check` stays green, no `unsafe` (workspace lint).
10. **Accessibility**: follow `a11y.rs` patterns (roles, labels, keyboard).
11. **Done means**: `cargo fmt --all`, `cargo clippy --workspace
    --all-targets -- -D warnings`, `cargo test --workspace` green; real
    end-to-end tests against real servers gated behind env vars with a
    `scripts/e2e-<slug>.sh` that sets them up; GUI checked on screen (Xvfb +
    xdotool + screenshots actually looked at) in dark and light, and German.
12. **Commits**: author and committer `meetdhruva
    <268780292+meetdhruva@users.noreply.github.com>`; no `Co-Authored-By`,
    `Claude-Session` or any other trailer (repository owner's instruction).
13. **Report**: what works and how each item was verified (e2e / unit / GUI),
    what was simplified or not done, new settings/shortcuts, limitations.

## 1. Persistent sessions (`persist`)

*Why*: the most-voiced pain with other clients is losing running programs on
sleep, network drops or closing the app.

- `HostProfile.persist: PersistMode { Off, Tmux }` (serde default `Off`) and
  `Settings.persist_default: bool`. SSH only.
- When on and `tmux` exists on the server, the shell runs inside a tmux
  session on a **private server** (`tmux -L hostwick -f /dev/null`), so the
  user's own tmux config and sessions are untouched. Session name
  `hw-<8 hex of profile id>-<slot>`; the slot is stored in the pane layout so
  reconnect, restore-tabs and reopen-closed-tab reattach the same session.
- tmux must be invisible: no status line, **no prefix key** (every key
  reaches the shell), mouse handled by us, alternate screen disabled for the
  outer terminal (`terminal-overrides` `smcup@:rmcup@`) so output keeps
  flowing into our native scrollback; on reattach replay history with
  `capture-pane -e -S -<n>` before attaching.
- OSC 7 / OSC 133 / title must still reach us (`allow-passthrough` on tmux ≥
  3.3 with wrapped sequences in the integration snippet; fall back to
  polling `#{pane_current_path}`). Verify ZMODEM/trzsz, mouse reporting,
  resize, 24-bit colour, broadcast and session logging through tmux; document
  what does not work.
- Lifecycle: disconnect / app exit leaves the session; **Close pane** ends it
  (confirm if a foreground program other than the shell is running); a
  "Sessions on this host" list (host menu + palette) shows left-behind
  sessions with age and command, attach or end them.
- No tmux on the server: connect normally, show one notice per host with the
  install hint. Never install anything.
- Owner: `crates/hostwick-ssh/src/persist.rs` (or `hostwick-term`),
  `apps/desktop/src/terminal/persist.rs`, `app/persist.rs`.

## 2. Importers (`import`)

*Why*: the cheapest adoption lever is "all my hosts are here in a minute".

- Add to `hostwick-import`: MobaXterm (`MobaXterm.ini`, `.mxtsessions`,
  registry), SecureCRT (session `.ini` tree, XML export), Xshell (`.xsh`
  tree), Tabby (`config.yaml`), mRemoteNG (`confCons.xml`), Royal TS/TSX
  (unencrypted `.rtsz`/CSV export), Termius (whatever it really exports —
  research it; if there is no readable export, document the route through
  ssh config/CSV instead of guessing), generic CSV, and
  Remmina/KDE/GNOME connection files if cheap.
- Map folders, port, user, key file, jump/proxy, port forwards, colours/
  environment where the source has them. RDP/VNC/other protocol entries are
  counted and reported as skipped.
- **Never decrypt or import stored passwords** from other tools; report
  "password not imported" per host.
- Formats come from real files or vendor documentation; fixtures in
  `tests/fixtures/`. Wire into: first-run scan (auto-detect default
  locations per OS), Import menu, palette, CLI `hostwick import <kind>`.
- Export: `hostwick export ssh-config|csv|json` and the same in the app.
- Owner: `crates/hostwick-import/src/<tool>.rs`, `firstrun.rs` hooks.

## 3. AI assistant (`ai`)

*Why*: every new client ships it; the open complaint is privacy.

- New crate `hostwick-ai`: `trait Provider` with streaming chat; providers
  **Anthropic API** and **OpenAI-compatible** (covers OpenAI, Ollama, LM
  Studio, llama.cpp, vLLM via base URL + model). API key in the vault.
- **Off until configured.** Nothing leaves the machine before the user has
  chosen a provider, and each request shows exactly what will be sent
  ("Context: 42 lines from web01") with an editable preview on first use and
  on demand.
- Features: (a) ask in plain language → proposed command with a short
  explanation; (b) explain selected output / the last command's output (OSC
  133 boundaries when available); (c) "fix it" for a failed command.
- **The assistant never runs anything.** A proposal is inserted at the
  prompt (bracketed paste, no Enter) or copied; the user presses Enter.
  Control characters are stripped from proposals; destructive patterns
  (`rm -rf`, `dd`, `mkfs`, `DROP`, `shutdown`, `> /dev/…`, force pushes…)
  show a warning.
- Redaction before sending: private-key blocks, password prompts and what
  was typed after them, common token formats, `Authorization:` headers,
  values of env vars named like secrets. Unit-tested.
- Per-host "never send content from this host"; prod-environment hosts
  default to that and need an explicit per-request confirmation to override.
- Terminal output is untrusted prompt input: system prompt hardening, and
  model output is only ever displayed or placed in the proposal box.
- UI: side panel (`Ctrl+Shift+I`), streaming, cancel, per-tab history kept in
  memory only. Settings → AI: provider, base URL, model, key, redaction
  preview, "test connection".
- Owner: `crates/hostwick-ai`, `apps/desktop/src/ai/`.

## 4. Themes (`themes`)

*Why*: customisation is a top Termius request; good-looking terminals get
screenshotted and shared.

- `ColorScheme { name, fg, bg, cursor, selection, ansi[16], … }` in core;
  `Settings.color_scheme`, `Settings.custom_schemes` (synced),
  `HostProfile.color_scheme: Option<String>` override.
- Import: iTerm2 `.itermcolors`, Windows Terminal JSON (single scheme or
  `settings.json` schemes array), Alacritty TOML/YAML, Kitty/Ghostty conf,
  base16 YAML, Xresources. Export: Windows Terminal JSON + Alacritty TOML.
- Built-in gallery of ~20 well-known schemes with compatible licences
  (credit them in a `THEMES.md`), light and dark, paired so "follow the OS
  theme" switches both app chrome and scheme.
- Picker (`Ctrl+Shift+Y`, palette, Settings → Appearance) with live preview
  on the focused terminal, search, import by file or paste.
- Cursor style (block/bar/underline, blink), line height, letter spacing,
  minimum-contrast option, background opacity only if GPUI supports it
  properly on all three OSes.
- The environment (prod) ribbon and keyword highlighting must stay legible
  on every built-in scheme (test contrast).
- Owner: `crates/hostwick-core/src/scheme.rs`, `apps/desktop/src/themes/`,
  `terminal/colors.rs`.

## 5. More file protocols (`fileproto`)

*Why*: WinSCP users who need FTP, S3 or WebDAV cannot fully switch.

- New crate `hostwick-cloudfs` with `FtpFs`, `S3Fs`, `WebDavFs` implementing
  `RemoteFs`, so the file browser, transfers, sync, edit-in-editor, preview
  and the CLI work unchanged.
- `Protocol` gains `Ftp(FtpSettings { tls: None|Explicit|Implicit, passive
  })`, `S3(S3Settings { region, bucket, endpoint, path_style })`,
  `WebDav(WebDavSettings { https, base_path })`. These are files-only hosts:
  no terminal actions; double-click opens files. Secret (password / S3
  secret key) via the vault like any password; S3 access key id is `user`.
- TLS verified by default; an untrusted certificate prompts like a host key
  and is pinned on acceptance. Plain FTP shows "password is sent
  unencrypted" before the first connect.
- Resume where the protocol allows (FTP `REST`, HTTP `Range`), S3 multipart
  for large uploads, pagination for big listings, timeouts and keepalive
  (`NOOP`). Capabilities a protocol lacks (chmod on S3, symlinks…) return
  `FsError::Unsupported` and the UI hides them.
- S3 must work with AWS, MinIO, Cloudflare R2, Backblaze B2 and Wasabi
  (path-style + custom endpoint); test against MinIO. FTP against vsftpd or
  pyftpdlib (plain, explicit and implicit TLS, passive). WebDAV against a
  real server (wsgidav / nginx-dav / rclone serve webdav).
- Host editor: protocol picker shows the right fields; importers may map
  FTP/S3/WebDAV sites (coordinate through this ADR only: importers emit them
  only if this enum exists at merge time).
- Owner: `crates/hostwick-cloudfs`, `hostwick-sftp/src/factory.rs` hook,
  `hostform.rs` protocol section, `backend.rs` `open_remote`.

## 6. Tunnel manager (`tunnels`)

*Why*: forwards today only run while a terminal is open.

- A **Tunnels** view (`Ctrl+Shift+J`, sidebar button, palette): every
  forward of every host in one list; start/stop each without a terminal
  (uses `ConnectionPool`; the connection stays up while a tunnel needs it).
- Status per tunnel: stopped / connecting / listening / error (port in use,
  auth failed…), open connections, bytes in/out, uptime. Auto-reconnect with
  backoff. Auth prompts go through the normal prompt path.
- Add/edit/remove local, remote and dynamic forwards here (writes the
  profile's `forwards`); per-forward `auto_start` (start with the app) and
  an optional label; "Copy address", "Open in browser" for local forwards.
- Binding to non-loopback addresses shows a warning and needs confirmation.
- Terminals opened later reuse the already-running forwards instead of
  failing with "address in use". Running tunnels are restored on restart
  (only those marked auto-start) and shown in the status bar count.
- CLI: `hostwick tunnel list|up <host> [name]|down` (foreground, Ctrl+C
  stops), JSON output.
- Owner: `crates/hostwick-ssh/src/tunnels.rs`, `apps/desktop/src/tunnels/`.
